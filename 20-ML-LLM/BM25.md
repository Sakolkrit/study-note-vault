# BM25

A classic **keyword search score**. It ranks documents by how well their words match the words in your question, with rare words counting more.

## 🟢 1. Simple (age 12)
You search a pile of pages for "teddy bear honey". BM25 gives each page a score. A page scores higher if it contains your words, **especially the unusual ones** ("honey" is a better clue than "the"). It also does not let a page win just by repeating a word 100 times, and it does not unfairly favour very long pages.

**Example:** Looking for "honey". Page A says "honey" twice in a short page. Page B mentions it once in a huge page. Page A gets the higher score.

## 🔵 2. How it works
1. Split the question and each document into words.
2. For each question word, ask **how rare** it is: a word found in almost every document tells you little, a word found in one document tells you a lot. That rarity weight is called **IDF** (inverse document frequency).
3. Count **how often** the word appears in the document (the term frequency).
4. More occurrences raise the score, but with **diminishing returns**: the tenth "honey" adds much less than the first.
5. **Length correction:** a long document naturally contains more words, so its counts are scaled down a bit.
6. Add up the scores of all question words. The document with the highest total is the best match.
7. In a [[RAG]] system this is **keyword retrieval**, as opposed to **semantic search**, which compares [[Embedding]]s of meaning. The lecture lists three options for the first step: semantic search, BM25, or a hybrid of both. Keywords are good for exact names and rare terms; embeddings are good for paraphrases.

## 🟠 3. Technical detail
- **Two settings:** $k_1$ controls how fast repeated words stop mattering (typically around 1.2 to 2), and $b$ controls how strongly length is corrected (0 means ignore length, 1 means full correction; 0.75 is common). The values 1.5 and 0.75 in the code are my choice; the usual defaults are from memory.
- **IDF has several versions.** The code uses $\ln\!\big(\frac{N-n+0.5}{n+0.5}+1\big)$, a common form that cannot go negative. Other libraries use slightly different forms, so scores differ between tools even though the ranking is usually similar.
- **No learning needed:** BM25 uses only counts. Nothing is trained, which makes it fast and a strong baseline.
- **Weakness:** it only matches words. "Cuddly" and "teddy" are unrelated to it unless the exact word appears. The lecture contrasts this with embedding search ([[Embedding Model]]), where a query and a chunk are compared by meaning.
- **Hybrid search:** combine the keyword score and the embedding score (the lecture lists this as method 3), then optionally re-rank the shortlist with a stronger model.
- **Where it fits:** the first stage, candidate retrieval, whose goal is high recall; a re-ranker later aims for precision ([[Retrieval Metrics]]).
- **Origin:** developed in information-retrieval research by Robertson and colleagues (from memory; I did not check the references).

```python
import math
from collections import Counter
docs = ['teddy bear reads a book', 'the bear likes honey and honey cake', 'paris is a city in france', 'a cuddly teddy bear sleeps all day long in the soft warm bed']
toks = [d.split() for d in docs]
N = len(docs); avgdl = sum(map(len, toks)) / N
k1, b = 1.5, 0.75
df = Counter(w for t in toks for w in set(t))
def idf(w): return math.log((N - df[w] + 0.5) / (df[w] + 0.5) + 1)          # one common form of the rarity weight
def bm25(query, i):
    tf = Counter(toks[i]); dl = len(toks[i]); s = 0.0
    for w in query.split():
        f = tf[w]
        s += idf(w) * f * (k1 + 1) / (f + k1 * (1 - b + b * dl / avgdl))
    return s
print('documents:', N, '| average length', avgdl, '| bear appears in', df['bear'], 'documents, honey in', df['honey'], ', paris in', df['paris'])
print('idf: bear', round(idf('bear'), 3), '| honey', round(idf('honey'), 3), '| paris', round(idf('paris'), 3))
for q in ('teddy bear', 'honey', 'paris city'):
    print(f'query {q!r:14s} scores', [round(bm25(q, i), 3) for i in range(N)], '-> best document', max(range(N), key=lambda i: bm25(q, i)))
# by hand for query 'honey' on document 1: f = 2 (honey twice), dl = 7
f, dl = 2, len(toks[1])
print('by hand, honey in doc 1:', round(idf('honey') * f * (k1 + 1) / (f + k1 * (1 - b + b * dl / avgdl)), 3))
# length normalisation: the same word count in a longer document scores lower
print('teddy: doc 0 (5 words) vs doc 3 (13 words), both contain it once:', round(bm25('teddy', 0), 3), 'vs', round(bm25('teddy', 3), 3))
# saturation: repeating a word keeps raising the score, but less and less
print('score for a word repeated f times in an average-length document:', [round(1.0 * f * (k1 + 1) / (f + k1), 3) for f in (1, 2, 4, 8, 100)])
```

## 🔴 4. Deep / formal
**The rarity weight (IDF).** With $N$ documents, of which $n_w$ contain the word $w$:

$$
\text{idf}(w)=\ln\!\left(\frac{N-n_w+0.5}{n_w+0.5}+1\right)
$$

**Where:**
- $N$ is the number of documents and $n_w$ is the number of documents that contain $w$.
- The $0.5$s are small corrections that keep the formula well behaved when $n_w$ is $0$ or $N$.
- The $+1$ inside keeps the result positive. $\ln$ is the natural logarithm.
- **Matters:** a word in almost every document gets a weight near $0$ and a word in few documents gets a large weight, so common words stop dominating. This is the version I used; other versions exist.

**Example (tiny numbers):** $N=4$ documents.
- "bear" is in 3 of them: $\ln\!\big(\frac{4-3+0.5}{3+0.5}+1\big)=\ln(1.4286)=\mathbf{0.357}$.
- "honey" is in 1 of them: $\ln\!\big(\frac{4-1+0.5}{1+0.5}+1\big)=\ln(3.333)=\mathbf{1.204}$.
- Meaning: the rare word "honey" counts about 3.4 times as much as the common word "bear".

**The BM25 score.** For a question $q$ and a document $d$:

$$
\text{BM25}(q,d)=\sum_{w\in q}\text{idf}(w)\cdot\frac{f_{w,d}\,(k_1+1)}{f_{w,d}+k_1\left(1-b+b\,\dfrac{|d|}{\text{avgdl}}\right)}
$$

**Where:**
- $f_{w,d}$ is how many times word $w$ appears in document $d$, and $|d|$ is the length of $d$ in words.
- $\text{avgdl}$ is the average document length in the collection.
- $k_1$ sets how quickly extra repeats stop helping, and $b$ sets how strongly long documents are penalised.
- The sum runs over the words of the question.
- **Matters:** the fraction grows with $f$ but levels off at $k_1+1$. Without the length term, long documents would win by having more words. Without IDF, common words would dominate.

**Example (tiny numbers):** question "honey", document 1 ("the bear likes honey and honey cake"), $f=2$, $|d|=7$, $\text{avgdl}=7.75$, $k_1=1.5$, $b=0.75$.
- Length factor: $1-0.75+0.75\cdot7/7.75=0.25+0.677=0.927$.
- Denominator: $2+1.5\cdot0.927=3.391$. Numerator: $2\cdot2.5=5$. Fraction $=1.474$.
- Score $=1.204\times1.474=\mathbf{1.775}$ (the code prints the same).
- Meaning: the only document with "honey" gets a clear lead, and the others score $0$.

**Further notes:**
- **Saturation (code):** for a word repeated $1,2,4,8,100$ times in an average-length document the fraction is $1.0,1.43,1.82,2.11,2.46$, so 100 repeats give less than 2.5 times the score of one.
- **Length (code):** "teddy" appears once in both a 5-word and a 13-word document, and scores $0.825$ against $0.531$.
- **Not covered:** query-term frequency weighting, stemming, stop words, and efficient indexes.

**What came before, and how this improved on it:**
- **Before:** plain keyword counting, where the score is the number of query words found (or raw term counts, from memory), and the TF-IDF family.
- **Its limit:** repeating a word keeps raising the score without limit, and long documents win by having more words.
- **What changed:** saturating term frequency and length normalisation on top of an IDF weight (from memory; I did not check the original papers).
- **How much better:** I did not compare against raw counting on a real collection. In the code, a word repeated 100 times scores 2.46 where raw counting would give 100, and a longer document scores $0.531$ against $0.825$ for the same single occurrence.
