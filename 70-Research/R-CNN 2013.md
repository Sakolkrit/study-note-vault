# R-CNN 2013

> **In one line for a 12-year-old:** First suggest about 2,000 boxes where an object might be. Then squash each box to the same size and let a picture-recognising network say what is inside it.

*Full title: "Rich feature hierarchies for accurate object detection and semantic segmentation" (arXiv 1311.2524; first submitted 11 Nov 2013 and I read version 5 of 22 Oct 2014 (dates from the arXiv listing), so some numbers, such as the OverFeat comparison, were added after the first version of 2013). Layout follows [[Attention Is All You Need 2017]] and [[Faster R-CNN 2015]]. Marks: "(paper, section)", "(general knowledge)", "(mine)".*

## The problem
Image classification says what is in a picture. [[Object Detection]] must also say **where**, and there can be many objects. Detection scores on the PASCAL VOC data set "plateaued in the last few years", and the best systems were "complex ensemble systems" mixing several hand-made image features with context (paper, abstract and 1). Two difficulties are named: how to find the place of an object with a deep network, and how to train a large network when "labeled training data is scarce" (paper, 1).

## What people did before
- **Hand-made features, SIFT and HOG,** the "blockwise orientation histograms" that the field had used for a decade. Progress "was slow during 2010-2012, with small gains obtained by building ensemble systems" (paper, 1). The strongest single baseline was the deformable part model (DPM, 33.4% mAP on VOC 2010; paper, Table 1).
- **The UVA system** (Uijlings et al.): the same region proposals as R-CNN, but each region described by a four-level spatial pyramid of SIFT-type features and classified with a non-linear SVM. 35.1% mAP on VOC 2010 (paper, 2.4 and Table 1).
- **CNNs as sliding-window detectors,** used for about two decades on constrained objects such as faces and pedestrians, with only two convolution and pooling layers to keep the position precise (paper, 1). The authors considered it for their 5-layer network and rejected it: units high in the network have receptive fields of 195 by 195 pixels and strides of 32 by 32 pixels, "which makes precise localization within the sliding-window paradigm an open technical challenge" (paper, 1; see [[Receptive Field]]).
- **Localisation as regression** (Szegedy et al., concurrent): a network predicts the box directly. The paper quotes 30.5% mAP on VOC 2007 for that, against 58.5% for R-CNN (paper, 1).
- **OverFeat,** a sliding-window CNN, compared head to head in version 5 on the 200-class ILSVRC2013 detection data (paper, 1 and 5).
- **Unsupervised pre-training then supervised fine-tuning,** the usual answer to scarce labels (paper, 1).

## The idea
Do not slide a window. Use the "recognition using regions" paradigm (paper, 1): a [[Selective Search]] step proposes about 2,000 category-independent boxes, each box is warped to 227 by 227 pixels and passed through a CNN that yields a 4,096-number description, and one linear [[Support Vector Machine]] per class scores that description. Second idea: since there are few detection labels, pre-train the CNN on the big ImageNet classification data with image labels only, then fine-tune it on warped detection boxes ([[Transfer Learning]], [[Fine-tuning]]). The name: **R-CNN, Regions with CNN features** (paper, 1).

## The method, step by step
The paper has no single architecture figure that I can show: its Figure 1 (the four-step overview) is under arXiv's non-exclusive licence, not an open one, and I found no free redrawing of it on Wikimedia Commons (a search returned only unrelated PDFs). So the steps are written out, and nothing is copied.

The system has three modules (paper, 2): region proposals, a CNN that turns each region into a fixed-length vector, and class-specific linear SVMs. Everything is **per box**: the CNN runs once for every proposal.

### Test time (paper, 2.2)
1. **Propose.** Run selective search in its "fast mode" on the image to get about 2,000 boxes.
   - *What it does:* gives candidate places for objects, whatever the class.
   - *Why it matters:* it turns "search every position and size" into "check 2,000 plausible boxes". The authors say R-CNN is "agnostic to the particular region proposal method" and used selective search "to enable a controlled comparison with prior detection work" (paper, 2.1).
2. **Warp.** Dilate each box so that, at the warped size, there are exactly p = 16 pixels of context around the original box, then stretch all pixels to 227 by 227, "regardless of the size or aspect ratio" (paper, 2.1).
   - *What it does:* makes every region fit the network's fixed input.
   - *Why it matters:* the network (the one from [[AlexNet 2012]]) needs a fixed size. In a pilot, warping with context beat the alternatives "by a large margin (3-5 mAP points)" (paper, Appendix A); more options were left as "future work".
3. **Describe.** Push the warped pixels, minus the mean image, through five convolution layers and two fully connected layers to get a 4,096-number vector (paper, 2.1).
4. **Score.** Multiply the 2000 by 4096 feature matrix with the 4096 by N matrix of SVM weights (N classes) in one matrix product (paper, 2.2).
5. **Prune.** For each class separately, apply greedy [[Non-Maximum Suppression]]: drop a box if its [[Intersection over Union]] with a higher-scoring kept box is above a learned threshold (paper, 2.2).
6. **Refine (optional).** A class-specific linear regressor on the CNN's pool5 features moves the box slightly (Appendix C; see the equations below).

*Why the cost is shared:* the CNN's parameters are shared across all classes, and its 4,096-number features are about two orders of magnitude smaller than the UVA system's (360,000 against about 4,000). So the time for proposals and features (13 s per image on a GPU, 53 s on a CPU; paper, 2.2) is the same for 20 classes or for thousands; only the matrix product grows.

### Training (paper, 2.3)
1. **Pre-train** the CNN on ILSVRC2012 classification with image-level labels only. The result is close to the original: "a top-1 error rate 2.2 percentage points higher" on the validation set, which the paper blames on "simplifications in the training process".
2. **Fine-tune** on warped proposals. Replace the 1000-way output layer with a new random (N + 1)-way layer (N = 20 for VOC, 200 for ILSVRC2013; the +1 is "background"), and continue SGD with a learning rate of 0.001, one tenth of the pre-training rate, "which allows fine-tuning to make progress while not clobbering the initialization" (paper, 2.3; see [[Stochastic Gradient Descent]], [[Learning Rate]]). A proposal with IoU of at least 0.5 against a ground-truth box counts as a positive for that class; the rest are background. Each mini-batch has 32 positive and 96 background windows (128 in all; my arithmetic: 25% positives), because positives "are extremely rare compared to background".
3. **Train one linear SVM per class** on the fine-tuned features. Here only the ground-truth boxes are positives, and a proposal with less than 0.3 IoU against every instance of the class is a negative. The threshold 0.3 came from a grid search over 0 to 0.5 in steps of 0.1: choosing 0.5 "decreased mAP by 5 points" and 0 decreased it by 4 points (paper, 2.3). Proposals in between are ignored. Because the data do not fit in memory, [[Hard Negative Mining]] is used, and "mAP stops increasing after only a single pass over all images".
4. **Train the box regressors** (Appendix C).

**Why two different labelling rules?** The paper explains it (Appendix B): the SVM rule was chosen first, when the CNN was only a fixed feature extractor. When fine-tuning was added, using that same rule "was much worse". The authors' conjecture, not proved, is that the looser 0.5 rule adds many "jittered" positives (about 30 times more positives), which the whole network needs to avoid [[Overfitting]] when fine-tuned. **Why SVMs at all?** They tried the fine-tuned network's own 21-way [[Softmax]] as the detector: VOC 2007 mAP fell from 54.2% to 50.9% (paper, Appendix B). They expect a gap-closing fix may exist, "which would simplify and speed up R-CNN training".

### Size and cost check (mine)
Computed in `rcnn_demo.py` (Python 3.9.6, no GPU; I rebuilt the layer sizes from the standard grouped five-convolution network that the paper cites, not from the paper's table):

| Part | Parameters (mine) |
|---|---|
| conv1 to conv5 | 2,334,080 |
| fc6 (9216 to 4096) | 37,752,832 |
| fc7 (4096 to 4096) | 16,781,312 |
| fc8 (1000-way) | 4,097,000 |
| All | 60,965,224 |

- fc7 is 16.78 million parameters, matching the paper's "about 16.8 million", and is 29.5% of the total without fc8, matching the paper's "29%" (paper, 3.2). The convolution layers are 4.1% of the total without fc8 (3.8% with it), while the paper says pool5 features are "computed using only 6% of the CNN's parameters". I could not reproduce 6%; I do not know how the paper counted, so I do not claim either number is wrong.
- The new (N + 1)-way layer has 86,037 parameters for N = 20 and 823,497 for N = 200 (mine).
- Run time, one image: 2000 × 4096 × N multiply-adds is 1.64e8 for 20 classes and 8.19e11 for 100,000 classes. The weights for 100,000 classes are 4096 × 100,000 × 4 bytes = 1.64e9 bytes = 1.53 GiB (mine), which agrees with the paper's "just 1.5GB" (paper, 2.2). The same sum for the UVA features, 360,000 × 100,000 × 4 bytes, is 134 GiB (mine), the paper's "134GB".

## The equations
Only one part of the paper is written as formulas: the bounding-box regression of Appendix C. (The detection score is a plain dot product of the 4,096-number feature and the SVM weights, which the paper does not number.)

**1. Moving a proposal to a better box** (paper, Appendix C; the paper does not number it)

$$
\hat G_x = P_w\, d_x(P) + P_x,\quad \hat G_y = P_h\, d_y(P) + P_y,\quad \hat G_w = P_w \exp(d_w(P)),\quad \hat G_h = P_h \exp(d_h(P))
$$

**Where:**
- $P=(P_x,P_y,P_w,P_h)$: the proposal, as the centre $x$, centre $y$, width and height in pixels.
- $\hat G$: the predicted improved box, in the same four numbers.
- $d_x,d_y,d_w,d_h$: four learned functions of the proposal's pool5 features, each a linear function $w_\star^{\top}\phi_5(P)$ (paper, Appendix C), with one set of weights per object class.

**Matters:**
- $d_x$ and $d_y$ are multiplied by the proposal's own width and height: the shift is "scale-invariant", so a 10% shift is 10% of the box whether the box is small or large.
- $d_w$ and $d_h$ sit inside an exponential: the change is in "log-space", the width cannot become negative, and doubling and halving are the same size of step (general knowledge, which the paper does not spell out).
- Without this stage, mislocalised boxes stay mislocalised. The paper's error analysis found them to be "the dominant error mode" and the regression raised VOC 2007 mAP from 54.2 to 58.5 (paper, 1 and Table 2).

**Example (tiny numbers):** proposal $P=(100,100,80,60)$ and ground truth $G=(110,95,100,54)$ (my numbers; `rcnn_demo.py`).
- Targets from equation 2 below: $t_x=(110-100)/80=0.125$, $t_y=(95-100)/60=-0.0833$, $t_w=\ln(100/80)=0.2231$, $t_h=\ln(54/60)=-0.1054$.
- Decoding with $d=t$: $\hat G_x=80\times0.125+100=110$, $\hat G_y=60\times(-0.0833)+100=95$, $\hat G_w=80\,e^{0.2231}=100$, $\hat G_h=60\,e^{-0.1054}=54$. The run printed `(110.0, 95.0, 100.0, 54.0)`.
- Meaning: a perfect regressor would recover the ground-truth box exactly from the proposal; a real one predicts $d$ from features and is only roughly right.

**2. The regression targets and the training objective** (paper, Appendix C)

$$
t_x=\frac{G_x-P_x}{P_w},\quad t_y=\frac{G_y-P_y}{P_h},\quad t_w=\ln\frac{G_w}{P_w},\quad t_h=\ln\frac{G_h}{P_h},\qquad
\mathbf w_\star=\arg\min_{\hat{\mathbf w}_\star}\sum_{i=1}^{N}\bigl(t^{i}_\star-\hat{\mathbf w}_\star^{\top}\phi_5(P^{i})\bigr)^{2}+\lambda\lVert\hat{\mathbf w}_\star\rVert^{2}
$$

**Where:**
- $t_\star$ ($\star$ is $x$, $y$, $w$ or $h$): the target the regressor should output for a pair of proposal $P^i$ and ground truth $G^i$.
- $\phi_5(P)$: the pool5 feature vector of the proposal.
- $\hat{\mathbf w}_\star$: the weights being learned, one vector per output and per class; $N$ is the number of training pairs.
- $\lambda$: the weight of the regularisation term; the paper sets $\lambda=1000$ using a validation set (paper, Appendix C). This is ridge regression, "solved efficiently in closed form" ([[Ridge Regression]], [[Regularization]]).

**Matters:**
- The squared-error part fits the targets; the $\lambda$ part keeps the weights small. "Regularization is important" (paper, Appendix C): there are 9,216 features, so without a penalty the fit can chase noise.
- The paper also says the pairs must be chosen with care: a proposal is used only if its best-matching ground-truth box has IoU above 0.6 (a threshold chosen on the validation set); a far-away proposal would give "a hopeless learning problem".
- Iterating (re-score the new box and regress again) "does not improve" results (paper, Appendix C), so it is done once.

**Example (tiny numbers):** a toy with one feature, no bias and three pairs $(\phi,t)=(1,0.1),(2,0.2),(3,0.3)$ (my toy, not the paper's data).
- With one weight the minimiser is $w=\sum\phi t/(\sum\phi^2+\lambda)$. The sums are $\sum\phi t=1.4$ and $\sum\phi^2=14$.
- $\lambda=0$ gives $w=1.4/14=0.100$, the perfect fit. $\lambda=1$ gives $1.4/15=0.093$. $\lambda=1000$ gives $1.4/1014=0.00138$.
- Meaning: a large $\lambda$ shrinks the weight almost to zero. The paper's 1000 is large because its features are many and its data per class are not unlimited; I did not check how much regression gain each $\lambda$ gives.

## What they found
Headline numbers: mAP of 53.3% on VOC 2012, "more than 30% relative" better than the best before (abstract); 53.7% on VOC 2010 with bounding-box regression (Figure 1 caption and Table 1); 31.4% on the 200-class ILSVRC2013 detection test set against 24.3% for OverFeat (paper, 2.5). Each table below is **written by me, an AI, from the paper's table text.** Per-class columns are left out and only the last column, mAP, is kept.

### Against hand-made features on VOC 2010 (paper's Table 1)
| Method | mAP, VOC 2010 test (%) |
|---|---|
| DPM v5 | 33.4 |
| UVA | 35.1 |
| Regionlets | 39.7 |
| SegDPM | 40.4 |
| R-CNN | 50.2 |
| R-CNN with box regression (BB) | 53.7 |

**What each column is, and why it matters:**
- **mAP:** [[Mean Average Precision]]: the area under the precision-recall curve for each of the 20 classes, averaged (general knowledge). Higher is better. It is the headline score of PASCAL VOC.
- **Rows:** UVA and Regionlets use the same selective-search proposals as R-CNN, so they are "the most germane comparison" (paper). DPM and SegDPM use extra context re-scoring that the others do not (paper's table note).

**Summary: what the table shows.** R-CNN with regression is best (53.7), DPM is worst (33.4). The fairest comparison, UVA with the same proposals, goes from 35.1 to 53.7: 18.6 points, 53% relative (mine). Against SegDPM, the previous leader, it is 13.3 points, 33% relative (mine; the abstract's "more than 30%"). Caution: the submission count was low (the paper submitted to the test server once per variant), but these are single runs with no error bars.

## Questions I had, answered

**Why warp instead of crop?** A crop keeps the shape but needs a choice of what to do with the empty rest of the square. The paper tried a tight square with and without context and warping with and without context. Warping with p = 16 won by 3 to 5 mAP points (paper, Appendix A). Why warping wins it does not say.

**What do "pool5, fc6, fc7" mean?** The CNN has five convolution layers. pool5 is the max-pooled output of the fifth, a 6 × 6 × 256 = 9,216-number map. fc6 and fc7 are the two fully connected layers on top, each 4,096 wide (paper, 3.2).

**What is the fine-tuning's "+1"?** The new output layer has one output per object class plus one for "background". It exists so that most proposals, which contain no object, can be given a label instead of being forced into a class (paper, 2.3).

**If it is a two-step system, is it trained end to end?** No. The CNN is fine-tuned, then SVMs are fitted on its features, then box regressors on its pool5 features, in separate stages (paper, 2.3 and Appendix C). The next papers, [[Fast R-CNN 2015]] and [[Faster R-CNN 2015]], were about this, among other things.

**What does the feature-visualisation section show?** Each pool5 unit is used as a detector on 10 million held-out proposals and its top-scoring regions are shown (paper, 3.1). Some units match concepts such as people or text; others match textures and materials. I looked at no figure for this note.

## Why it mattered
It showed that a CNN trained for classification can be turned into a strong detector by looking at proposed regions, and that "supervised pre-training followed by domain-specific fine-tuning" works when detection labels are scarce (paper, abstract and 6). The authors conjecture the second idea will be effective "for a variety of data-scarce vision problems". Its weaknesses became the problems of the next papers: [[Fast R-CNN 2015]] (shared computation) and [[Faster R-CNN 2015]] (proposals inside the network).

## Limits and open questions
- **Slow:** one CNN pass per proposal; 13 s per image on a GPU and 53 s on a CPU (paper, 2.2). The paper says OverFeat is "about 9x faster" (about 2 seconds per image, quoted from the OverFeat paper), because its sliding windows share convolution computation, and speeding up R-CNN "remains as future work" (paper, 5).
- **Multi-stage training:** CNN, SVMs and regressors are fitted separately, and features are saved to disk for the SVM stage (the saving to disk is general knowledge, not stated in the parts I read).
- **Fixed, external proposals:** selective search is not part of the network and misses some objects (91.6% recall on ILSVRC2013).
- **Warping distorts objects**, and the paper tried few alternatives.
- **Softmax against SVM** left a 3.3-point gap (54.2 against 50.9) that the authors hope to close.
- **Heavy hand-set numbers:** p = 16, 0.5 and 0.3 for the labels, 0.6 and λ = 1000 for the regression; some were tuned on a validation set, but the paper tested only a few values for each.
- **Single runs with no error bars** on every table above.

#flashcards/research/concept #flashcards/topic/research-detection-segmentation How is the CNN fine-tuned in R-CNN?::Replace the 1000-way output with a random (N + 1)-way layer (N classes plus background); continue SGD at a learning rate of 0.001 (a tenth of pre-training); IoU of at least 0.5 with a ground-truth box is positive; batches of 32 positives and 96 background windows (paper, 2.3).

#flashcards/research/concept #flashcards/topic/research-detection-segmentation Why does R-CNN define positives differently for fine-tuning and for the SVMs?::History: the SVM rule (ground-truth boxes positive, IoU below 0.3 negative) was chosen first with a fixed CNN; using it for fine-tuning gave worse results. The looser 0.5 rule adds about 30 times more "jittered" positives, which the authors conjecture is needed to avoid overfitting (paper, Appendix B; the explanation is a conjecture).

#flashcards/research/concept #flashcards/topic/research-detection-segmentation Why does R-CNN train SVMs after fine-tuning instead of using the softmax output?::Using the fine-tuned 21-way softmax as the detector dropped VOC 2007 mAP from 54.2% to 50.9%; the authors think the fine-tuning labels do not stress precise localisation and the negatives were random rather than hard (paper, Appendix B).

#flashcards/research/concept #flashcards/topic/research-detection-segmentation Why does R-CNN scale to many classes cheaply?::The CNN is shared across classes and its 4,096-number features are small; per-class work is one dot product with the SVM weights. For 100,000 classes the weights are about 1.5 GB against 134 GB for the UVA features (paper, 2.2; I checked both with my arithmetic).

#flashcards/research/concept #flashcards/topic/research-detection-segmentation Which R-CNN layers matter without fine-tuning (VOC 2007)?::pool5 44.2, fc6 46.2, fc7 44.7 mAP: fc7 is worse than fc6, so about 29% of the parameters (16.8 million in fc7) can be removed without losing mAP; much of the power is in the convolution layers (paper, 3.2, Table 2).

#flashcards/research/concept #flashcards/topic/research-detection-segmentation How much did fine-tuning add in R-CNN, and where?::Best non-fine-tuned 46.2 to best fine-tuned 54.2 mAP: 8.0 points. Gains were larger for fc6 and fc7 (+6.9 and +9.5, my arithmetic) than for pool5 (+3.1), so pool5 features are general and the gain is in the new classifiers on top (paper, 3.2, Table 2).

#flashcards/research/formula #flashcards/topic/research-detection-segmentation Write R-CNN's bounding-box regression targets and explain each part.
?
$$t_x=\frac{G_x-P_x}{P_w},\quad t_y=\frac{G_y-P_y}{P_h},\quad t_w=\ln\frac{G_w}{P_w},\quad t_h=\ln\frac{G_h}{P_h}$$
- $P$: the proposal (centre x, centre y, width, height); $G$: the ground-truth box in the same form.
- $t_x,t_y$: shift of the centre as a fraction of the proposal's width and height (scale-invariant).
- $t_w,t_h$: log of the size ratio, so doubling and halving are equal steps and the width stays positive after the exponential.
- They are the targets of a ridge regression on pool5 features, one regressor per class (paper, Appendix C).

#flashcards/research/formula #flashcards/topic/research-detection-segmentation Write the R-CNN transformation that applies the four learned values to a proposal.
?
$$\hat G_x=P_w d_x(P)+P_x,\ \hat G_y=P_h d_y(P)+P_y,\ \hat G_w=P_w e^{d_w(P)},\ \hat G_h=P_h e^{d_h(P)}$$
- $d_\star(P)$: learned linear functions $w_\star^{\top}\phi_5(P)$ of the proposal's pool5 features.
- $\hat G$: the predicted improved box.
- Shifts are scaled by the proposal's size; size changes are in log space (paper, Appendix C).

#flashcards/research/example #flashcards/topic/research-detection-segmentation Proposal (100, 100, 80, 60) and ground truth (110, 95, 100, 54): what are R-CNN's regression targets?::tx = 10/80 = 0.125, ty = -5/60 = -0.0833, tw = ln(100/80) = 0.2231, th = ln(54/60) = -0.1054. Decoding them returns (110, 95, 100, 54) exactly (my arithmetic, run in Python).

#flashcards/research/concept #flashcards/topic/research-detection-segmentation In R-CNN's box regression, why lambda = 1000 and why only proposals with IoU above 0.6?::Regularisation matters with 9,216 features, so lambda was set to 1000 on a validation set; a proposal far from every ground-truth box gives "a hopeless learning problem", so only proposals with IoU above 0.6 (also chosen on validation) are used (paper, Appendix C).

#flashcards/research/example #flashcards/topic/research-detection-segmentation Toy ridge fit: points (1, 0.1), (2, 0.2), (3, 0.3), one weight, no bias. What is w for lambda 0, 1 and 1000?::w = 1.4 / (14 + lambda): 0.100, 0.093 and 0.00138. A large lambda shrinks the weight almost to zero (my own toy, not from the paper).

#flashcards/research/concept #flashcards/topic/research-detection-segmentation R-CNN against hand-made features on VOC 2010: what did it score?::R-CNN 50.2 and 53.7 with box regression against UVA 35.1, Regionlets 39.7, SegDPM 40.4 and DPM 33.4 mAP; against UVA (same proposals) that is +18.6 points, 53% relative (mine) (paper, Table 1).

#flashcards/research/concept #flashcards/topic/research-detection-segmentation What did a deeper network do for R-CNN?::Swapping the 8-layer network for the 16-layer VGG raised VOC 2007 mAP from 54.2 to 62.2 (58.5 to 66.0 with box regression), but its forward pass took about 7 times longer (paper, 3.3, Table 3).

#flashcards/research/concept #flashcards/topic/research-detection-segmentation How did R-CNN do on ILSVRC2013 detection, and what limited it?::31.4% mAP against 24.3% for OverFeat and 22.6% for the next competition entry; selective search had only 91.6% recall at 0.5 IoU there (about 98% on PASCAL), so the proposal step limits it (paper, 2.5, 4.2, Figure 3).

#flashcards/research/concept #flashcards/topic/research-detection-segmentation What is the main limit of R-CNN?::It runs a CNN pass on every proposal: 13 s per image on a GPU and 53 s on a CPU, about 9 times slower than OverFeat, which shares convolution across windows; training is also multi-stage (CNN, then SVMs, then regressors) (paper, 2.2, 5).

#flashcards/research/concept #flashcards/topic/research-detection-segmentation R-CNN: reading trail?::It reused the CNN of AlexNet, beat DPM-style detectors, and led to Fast R-CNN (shared convolution), Faster R-CNN (proposals in the network) and Mask R-CNN.
