# U-Net 2015

> **In one line for a 12-year-old:** A network shaped like the letter U: it shrinks the picture to understand what is in it, then grows it back to full size to say exactly where things are, with shortcuts that carry fine detail across. It works even when you have very few labelled pictures.

Paper: "U-Net: Convolutional Networks for Biomedical Image Segmentation", arXiv 1505.04597, version 1 of 18 May 2015, 8 pages. Marks: "(paper, section)" was read in the paper; "(general knowledge)" is my own background; "(mine)" is my own arithmetic, done in Python. This paper's arXiv licence is not open (the usual arXiv licence), so its own figures are not copied; a free redrawing is used instead.

## The problem
Deep networks were believed to need "many thousand annotated training samples" (abstract). In biomedical work that is out of reach: a person has to outline every cell by hand. And the task is not "what is in this picture" but **segmentation**: a class label for every single pixel, so the network must say where things are as well as what they are (paper, 1). See [[Image Segmentation]].

## What people did before
- **Sliding-window network (Ciresan et al.):** for each pixel, feed a small patch around it to a network that predicts that pixel's label. It "won the EM segmentation challenge at ISBI 2012 by a large margin" (paper, 1). It has two drawbacks the authors name: it is slow, because the network runs once per patch and the patches overlap so much work repeats; and there is a trade-off between knowing where (small patches) and seeing context (large patches need more pooling, which blurs the position) (paper, 1).
- **Multi-layer classifiers:** later approaches used features from several layers at once, to get both good localisation and context (paper, 1).
- **[[FCN 2014]], the fully convolutional network:** replace the fully connected layers with convolutions and add layers that upsample, so the output is a map. U-Net builds on it (paper, 1).

## The idea
Keep the fully convolutional design, but make the upsampling half a mirror image of the shrinking half, with many feature channels, and join them with shortcuts. The shrinking half ("contracting path") captures context. The growing half ("expansive path") restores the size so each pixel gets a label. At every size, the detailed features from the shrinking half are copied across and glued onto the upsampled ones, so the output layers have both "what" and "where" (paper, 1 and 2). Two training tricks make it work with very little data: heavy [[Data Augmentation]] with elastic deformations, and a loss weighted so that the thin gaps between touching cells are not ignored (paper, 1 and 3). Because the picture of the network is a U, it is called the u-net. See [[Convolutional Neural Network]].

What each column is, and why it matters:
- **Step:** where in the U we are. The left column of the U is the contracting path, the right is the expanding path.
- **Size in / after 2 convs:** the width of the (square) feature map in pixels. Every 3 by 3 convolution without padding loses 2 pixels (1 on each side), so two convolutions lose 4 (paper, 2). It matters because the sizes explain why the output (388) is smaller than the input (572) and why the copied maps must be cropped.
- **Channels:** how many feature maps are stacked. They double at every pooling (64, 128, 256, 512, 1024) and halve at every up-convolution (paper, 2). It matters because more channels at low resolution means the network can store richer context where it is cheap.
- **Then:** the operation that takes us to the next row, and the crop size of the skip connection (mine: the copied map is cut by 4, 16, 40 and 88 pixels on each side).

**Summary: what the table shows.**
- **The U shape:** size falls 572, 284, 140, 68, 32 and rises 28, 56, 104, 200, 392 (mine); channels rise 64 to 1024 and fall back to 64.
- **The biggest cost of unpadded convolutions:** 572 in, 388 out, which is a border of 92 pixels per side lost (mine). That border is exactly what the overlap-tile strategy (below) fills in.
- **Caution:** sizes are for this one example; the paper only says the input tile must be chosen so every 2 by 2 pooling sees an even size (paper, 2).

### Part by part
- **The contracting path (left side).**
  - *What it does:* repeats two 3 by 3 convolutions, each followed by a ReLU, then a 2 by 2 max pooling with stride 2, and doubles the channels after each pooling (paper, 2). See [[Convolution]] and [[Pooling|Max Pooling]].
  - *Why it matters:* each pooling halves the width, so each later neuron looks at a wider area of the original picture. This is how the network gets context ("is this blob inside a cell?").
- **The bottom of the U.**
  - *What it does:* two more convolutions at the smallest size (28 by 28 in the example) with 1024 channels (paper, Fig. 1).
  - *Why it matters:* it is the place with the widest view and the most channels; everything the network knows about context is gathered here.
- **The expansive path (right side): the up-convolution.**
  - *What it does:* each step upsamples the map and applies a 2 by 2 convolution (the "up-convolution") that halves the channels (paper, 2).
  - *Why it matters:* it undoes the shrinking, step by step, so that at the end there is one prediction per pixel. In FCN the upsampling part has few channels; here it has "a large number of feature channels, which allow the network to propagate context information to higher resolution layers", which makes the two halves symmetric (paper, 1).
- **The copy-and-crop shortcuts (skip connections).**
  - *What they do:* the feature map from the same level of the contracting path is cropped to the right size and glued (concatenated) onto the upsampled map, then two 3 by 3 convolutions follow (paper, 2).
  - *Why they matter:* the contracting path knows where edges are exactly but not what they mean; the upsampled path knows the meaning but its positions are coarse. Gluing them together lets the next convolution "assemble a more precise output" (paper, 1). The cropping is needed because the contracting maps are larger, having lost fewer border pixels (paper, 2).
- **The final 1 by 1 convolution.**
  - *What it does:* maps each 64-component feature vector at each pixel to the number of classes (paper, 2).
  - *Why it matters:* it turns features into class scores for every pixel. In total, 23 convolutional layers (paper, 2); my count: 10 in the contracting path and bottom, 12 in the expansive path (4 up-convolutions and 8 convolutions) and 1 final.
- **No fully connected layers; valid convolutions only.**
  - *What it does:* the network is fully convolutional and keeps only the "valid" part of each convolution, so every output pixel is computed from a full view (paper, 1).
  - *Why it matters:* it can be applied to images of any size, tile by tile.
- **The overlap-tile strategy.**
  - *What it does:* to segment a big image, cut it into tiles; to predict a tile you feed in a larger window around it, and where the window runs off the image edge, the missing pixels are made by mirroring the image (paper, 1 and Fig. 2). The input tile size is chosen so every pooling sees an even size.
  - *Why it matters:* it allows "seamless segmentation of arbitrarily large images" and the resolution is "otherwise limited by the GPU memory" (paper, 1).

The paper's Figure 2 (overlap-tile strategy), Figure 3 (HeLa cells, their ground truth and weight map) and Figure 4 (cell segmentation results) are microscope images from the authors; no free copies exist, so they are described but not shown.

## The core mechanism, step by step

**From a picture to a map of labels (my numbered paraphrase of paper, 2 and 3).**
1. **Cut a tile** from the image and mirror the missing border if the tile is at the edge.
2. **Go down:** convolve twice, pool; repeat four times, doubling channels each time. Remember each level's result.
3. **Bottom:** two convolutions with 1024 channels.
4. **Go up:** upsample, halve the channels with a 2 by 2 convolution, crop the remembered map from the same level and concatenate it, convolve twice; repeat four times.
5. **Label:** a 1 by 1 convolution gives, for each pixel, one score per class.
6. **Softmax:** turn the scores into probabilities per pixel (equation 1 below).
7. **Compare with the truth** with a weighted cross-entropy (equations 2 and 3) and update by stochastic gradient descent.

**Training setup (paper, 3).** Because of the unpadded convolutions the output is smaller than the input, so "we favor large input tiles over a large batch size and hence reduce the batch to a single image", and use a high momentum, 0.99, so that "a large number of the previously seen training samples determine the update". It uses the stochastic gradient descent of Caffe, and training takes about 10 hours on an NVidia Titan GPU with 6 GB (paper, 5).

**Data augmentation (paper, 3.1).** The key trick: random elastic deformations. Random displacement vectors are drawn on a coarse 3 by 3 grid (nine vectors), from a Gaussian with standard deviation 10 pixels; the per-pixel displacement is then found by bicubic interpolation. Dropout at the end of the contracting path adds more implicit augmentation. The paper calls elastic deformation "the key concept to train a segmentation network with very few annotated images".

## The equations

**1. The pixel-wise softmax** (paper, section 3, not numbered)

$$
p_k(\mathbf{x})=\frac{\exp\big(a_k(\mathbf{x})\big)}{\sum_{k'=1}^{K}\exp\big(a_{k'}(\mathbf{x})\big)}
$$

**Where:**
- $\mathbf{x}$: a pixel position in the image grid $\Omega$.
- $a_k(\mathbf{x})$: the raw score (activation) of class $k$ in the last feature map at that pixel.
- $K$: the number of classes.
- $p_k(\mathbf{x})$: the probability that the pixel belongs to class $k$; the paper calls it "the approximated maximum-function", close to 1 for the class with the biggest score and close to 0 for the others.

**Matters:** it turns arbitrary scores into probabilities that add up to 1 at each pixel, so a cross-entropy can compare them with the truth. Without the exponential, negative scores would not be probabilities. See [[Softmax]].

**Example (tiny numbers):** two classes (cell, background) and scores $a=(2,1)$ at one pixel.
- $e^{2}=7.389$ and $e^{1}=2.718$, sum $10.107$.
- $p=(0.731,\ 0.269)$.
- Meaning: the pixel is called "cell" with 73% confidence.

**2. The weighted cross-entropy energy** (paper, Eq. 1)

$$
E=\sum_{\mathbf{x}\in\Omega} w(\mathbf{x})\,\log\big(p_{\ell(\mathbf{x})}(\mathbf{x})\big)
$$

**Where:**
- $\ell(\mathbf{x})$: the true class of the pixel.
- $p_{\ell(\mathbf{x})}(\mathbf{x})$: the probability the network gave to that true class.
- $w(\mathbf{x})$: a weight for that pixel (equation 3), so some pixels count more.
- The sum runs over every pixel of the tile.

**Matters:** it measures how far the network is from the truth, pixel by pixel, and lets the training care more about some pixels. Note on the printed formula: as printed it has no minus sign, but $\log p$ is never positive, so minimising it as printed would drive the true-class probability to 0; the usual cross-entropy has a minus sign in front (my reading; the text says it "penalizes at each position the deviation of $p_{\ell(\mathbf{x})}(\mathbf{x})$ from 1").

**Example (tiny numbers):** from the softmax example, if the true class is "cell" ($p=0.731$) the pixel's loss is $-\ln0.731=0.313$; if the true class is "background" ($p=0.269$) it is $1.313$ (with weight 1).
- With a weight of $7.065$ (see equation 3) a wrongly called border pixel with true class background costs $7.065\times1.313=9.28$ (mine).
- Meaning: a confident right answer costs little, a wrong one costs a lot, and the weight multiplies the penalty.

**3. The weight map** (paper, Eq. 2)

$$
w(\mathbf{x})=w_c(\mathbf{x})+w_0\cdot\exp\!\left(-\frac{\big(d_1(\mathbf{x})+d_2(\mathbf{x})\big)^2}{2\sigma^2}\right)
$$

**Where:**
- $w_c(\mathbf{x})$: a weight that balances the class frequencies (so the rare class is not drowned out by the common one).
- $w_0$: how large the extra border weight can get; the paper sets $w_0=10$.
- $d_1(\mathbf{x})$: distance from the pixel to the border of the nearest cell; $d_2(\mathbf{x})$: distance to the border of the second-nearest cell.
- $\sigma$: how fast the extra weight dies away with distance; the paper sets $\sigma\approx5$ pixels.

**Matters:** where two cells touch, the thin background gap between them has a small $d_1+d_2$, so the exponential is close to 1 and the pixel is weighted up to $w_0$ more. Far from any pair of borders $d_1+d_2$ is large and the exponential is close to 0. Without it the network can call the gap "cell" and merge touching cells into one blob, which is cheap in plain cross-entropy because the gap has so few pixels.

**Example (tiny numbers):** $w_c=1$, $w_0=10$, $\sigma=5$.
- On the gap ($d_1+d_2=0$): $1+10\,e^{0}=11$.
- Near it ($d_1+d_2=5$): $1+10\,e^{-25/50}=1+10\times0.6065=7.065$.
- Further ($d_1+d_2=10$): $1+10\,e^{-100/50}=2.353$. Far away ($20$): $1.003$.
- Meaning: the weight is about 11 on the gap itself and falls to the normal 1 within a few cells' width.

**4. The weight initialisation** (paper, section 3, text formula)

$$
\text{std}=\sqrt{\frac{2}{N}}
$$

**Where:**
- $\text{std}$: the standard deviation of the Gaussian from which the starting weights of a layer are drawn.
- $N$: the number of incoming connections of one neuron; for a 3 by 3 convolution on 64 input channels, $N=9\cdot64=576$ (paper, 3).

**Matters:** the aim is that each feature map starts with about unit variance, "otherwise, parts of the network might give excessive activations, while other parts never contribute" (paper, 3). The 2 comes from the ReLU zeroing half of the values (general knowledge, from He et al., which the paper cites). Without a good start, a network with 23 layers and several paths may not train.

**Example (tiny numbers):** $N=576$.
- $2/576=0.00347$; the square root is $0.0589$.
- With 128 input channels, $N=1152$ and std $=0.0417$: wider layers get smaller starting weights.
- Meaning: starting weights are small numbers around 0.06, and they shrink as the layers get wider.

## What they found
The paper tests the u-net on three segmentation tasks (paper, 4): neuronal structures in electron microscope stacks (ISBI 2012 challenge) and two kinds of cell images in the ISBI cell tracking challenge 2015. The network is also fast: "less than a second" for a 512 by 512 image on a recent GPU (abstract).

What each column is, and why it matters:
- **Warping error:** a measure of how many topological mistakes (merged or split cells, holes) the segmentation has, allowing for small boundary shifts (general knowledge; the paper only names it). Lower is better. It is the ranking column.
- **Rand error:** 1 minus the Rand index, which counts how often pairs of pixels are correctly put in the same or in different cells (general knowledge). Lower is better.
- **Pixel error:** the fraction of pixels with the wrong label after thresholding (general knowledge). Lower is better.
- **Human values:** a person's own segmentation, as a reference.
- **Rank and group:** challenge entries; IDSIA is Ciresan et al., the sliding-window network. All three errors are computed on a secret test set by the organisers, from the network's probability map thresholded at 10 levels (paper, 4).

**Summary: what the table shows.**
- **Best on the ranking column:** u-net has the lowest warping error, 0.000353, about 16% lower than the sliding-window network's 0.000420 (mine). Its Rand error 0.0382 is 24% lower than that network's 0.0504 (mine).
- **Close call:** DIVE-SCI is only 0.000002 behind on warping error, and better on Rand error (0.0305) and pixel error (0.0584).
- **Caution:** u-net is not the best on all three measures. The paper itself says that in Rand error the only better algorithms use "highly data set specific post-processing" on the probability map of Ciresan et al. (one of them submitted 78 different solutions, footnote 1), while the u-net used no pre- or postprocessing (but averaged 7 rotated versions of the input). The humans are still far better: the u-net's warping error is about 70 times theirs (mine).

## Questions I had, answered

**Why does the output shrink, and is that a problem?** Every unpadded 3 by 3 convolution loses a pixel on each side, so a 572 by 572 input gives a 388 by 388 output (mine). It is on purpose: each output pixel then has a full view of the input around it, with no invented padding at the edges. To label a big image you feed overlapping tiles and mirror the missing edges (paper, 1).

**Why must the tile size be chosen so pooling sees an even size?** A 2 by 2 pooling with stride 2 needs an even width, otherwise a row is dropped and the later maps do not line up for the copy. In the example 572, 568, 284, 280, 140, 136, 68, 64 are all even before each pooling; a 573 tile would reach 569 (odd) before the first pooling (mine).

**Why not just let the network see the whole image once and skip the skip connections?** The deepest layers have seen a lot of context but their maps are tiny and coarse. The shortcuts bring back the fine positions from the high-resolution maps, which is what gives "precise localization" (abstract; paper, 1).

**Why weight the border pixels more?** In cell images the thin gap between two touching cells is a few pixels wide, so a plain loss barely notices if the network fills it in. The weight map gives those pixels a weight up to 11 times larger (example above), so the network learns to draw the line between the cells (paper, 3).

**Why are elastic deformations so useful here?** A tissue changes shape in realistic ways, so a deformed copy of a microscope image looks like a plausible new image. The network learns to be unaffected by them without annotated examples of them (paper, 1).

## Why it mattered
The paper shows that segmentation with very few labelled pictures is possible, if the architecture and augmentation are right. The U shape with copied shortcuts became the standard design for medical and many other segmentation tasks (from memory; the paper itself only claims it "can be applied easily to many more tasks").

## Limits and open questions
- Only three biomedical data sets are tested (paper, 4); how it fares on other pictures is not shown in the paper.
- The best Rand error on the EM challenge belongs to methods with data-set-specific postprocessing, so a gap remains there (paper, 4).
- The cell results are only for 2D images.
- The weight-map recipe has hand-set constants ($w_0=10$, $\sigma\approx5$); the paper gives no ablation of them.
- The paper reports no ablation of the skip connections or the augmentation, so how much each part contributes is not measured here (my reading).

It makes every score positive, so each value is a valid probability, and it exaggerates differences: scores $(2,1)$ give $(0.731,0.269)$, so the largest score takes most of the probability. That is why the paper calls it an approximated maximum function. Without it a negative score could not be a probability.

#flashcards/research/concept #flashcards/topic/research-detection-segmentation Write U-Net's weighted cross-entropy energy (paper's Eq. 1) and explain each symbol.
?
$$E=\sum_{\mathbf{x}\in\Omega} w(\mathbf{x})\,\log\big(p_{\ell(\mathbf{x})}(\mathbf{x})\big)$$
- $\ell(\mathbf{x})$: the true class at pixel $\mathbf{x}$; $p_{\ell(\mathbf{x})}$: the probability given to it; $w(\mathbf{x})$: that pixel's weight; the sum covers all pixels.
- It measures the distance from the truth per pixel, with some pixels counting more. As printed it lacks the usual minus sign (my reading), since $\log p\le0$.

#flashcards/research/concept #flashcards/topic/research-detection-segmentation Energy example: true class background with $p=0.269$, weight 1 versus weight 7.065. What are the losses?
?
Unweighted: $-\ln0.269=1.313$. Weighted by $7.065$: about $9.28$ (mine: $7.065\times1.313$). A wrong call on a border pixel is punished seven times as hard.

#flashcards/research/concept #flashcards/topic/research-detection-segmentation Why does the loss have a weight $w(\mathbf{x})$ at all?
?
Without it every pixel counts the same, and the thin gaps between touching cells are only a few pixels, so merging two cells costs almost nothing. With a weight of up to 11 on those gaps (example: $w_c=1$, $w_0=10$) the network is punished for merging them and learns to draw the border.

#flashcards/research/concept #flashcards/topic/research-detection-segmentation Write U-Net's weight map (paper's Eq. 2) and explain each symbol.
?
$$w(\mathbf{x})=w_c(\mathbf{x})+w_0\cdot\exp\!\left(-\frac{\big(d_1(\mathbf{x})+d_2(\mathbf{x})\big)^2}{2\sigma^2}\right)$$
- $w_c$: class-frequency balancing weight; $w_0=10$: the maximum extra border weight; $d_1,d_2$: distances to the nearest and second-nearest cell border; $\sigma\approx5$ pixels: how fast the extra weight fades.
- It gives the biggest weight to pixels squeezed between two cells and about the plain weight elsewhere.

#flashcards/research/concept #flashcards/topic/research-detection-segmentation Weight-map example: $w_c=1$, $w_0=10$, $\sigma=5$. What is $w$ for $d_1+d_2=0$, $5$, $10$ and $20$?
?
$11$, $1+10e^{-0.5}=7.065$, $1+10e^{-2}=2.353$, $1.003$ (my arithmetic). The weight is about 11 on the gap itself and back to the normal 1 within a short distance.

#flashcards/research/concept #flashcards/topic/research-detection-segmentation Why is $d_1+d_2$ squared and put inside an exponential in the weight map?
?
The exponential gives a smooth bump that is largest (1) when both distances are small, so only pixels close to two cells at once get the bonus. Squaring the sum makes it a Gaussian shape, flat near the gap and falling fast, so the bonus nearly vanishes a few pixels away (at $d_1+d_2=20$ the extra is $0.003$, mine). With a linear distance it would fade slowly and weight the whole background.

#flashcards/research/concept #flashcards/topic/research-detection-segmentation What does $\sigma$ do in the weight map, and what if it were bigger or smaller?
?
It is the width of the bump: at $d_1+d_2=10$ the extra weight is $10e^{-100/(2\sigma^2)}$, which is $0.039$ for $\sigma=3$, $1.353$ for $\sigma=5$ and $6.065$ for $\sigma=10$ (mine). A small $\sigma$ weights only the very thin gap; a large $\sigma$ spreads extra weight over a wide background area.

#flashcards/research/concept #flashcards/topic/research-detection-segmentation Write U-Net's weight initialisation and explain each symbol.
?
$$\text{std}=\sqrt{\frac{2}{N}}$$
- $\text{std}$: standard deviation of the Gaussian that draws the starting weights; $N$: the number of incoming connections of one neuron ($9\cdot64=576$ for a 3 by 3 convolution on 64 channels).
- It keeps each feature map at about unit variance so no part of the network starts with excessive or dead activations.

#flashcards/research/concept #flashcards/topic/research-detection-segmentation Initialisation example: $N=576$, then $N=1152$. What are the standard deviations?
?
$\sqrt{2/576}=0.0589$ and $\sqrt{2/1152}=0.0417$ (my arithmetic). Wider layers start with smaller weights.

#flashcards/research/concept #flashcards/topic/research-detection-segmentation Why does the initialisation have a 2 in it, and why divide by $N$?
?
Dividing by $N$ stops the sum of $N$ inputs from growing: the variance of a sum rises with $N$, so each weight's variance must fall as $1/N$ ($0.0589$ at $N=576$ against $0.0417$ at $N=1152$). The 2 compensates for the ReLU zeroing half the values (general knowledge, from the paper's cited He et al.). Without it a 23-layer network may blow up or fade.

#flashcards/research/concept #flashcards/topic/research-detection-segmentation What is U-Net's key data-augmentation trick and how is it made?::Random elastic deformations: random displacement vectors on a coarse 3 by 3 grid drawn from a Gaussian with standard deviation 10 pixels, then bicubic interpolation to every pixel. The paper calls it the key concept for training with very few annotated images.

#flashcards/research/concept #flashcards/topic/research-detection-segmentation How were U-Net's training batches and momentum chosen, and why?::A batch of one image with large input tiles, and momentum 0.99, so that many previously seen samples determine each update (paper, 3). It makes maximum use of GPU memory because unpadded convolutions make tiles lose a border.

#flashcards/research/concept #flashcards/topic/research-detection-segmentation How did U-Net do on the neuron EM challenge (paper's Table 1)?::Best warping error, 0.000353, about 16% lower than the sliding-window network's 0.000420 (my arithmetic); Rand error 0.0382 against 0.0504. DIVE-SCI is only 0.000002 behind and better on Rand error (0.0305) and pixel error (0.0584). Humans are far better, about 70 times lower warping error (mine).

#flashcards/research/concept #flashcards/topic/research-detection-segmentation Why is U-Net's win in Table 1 not a clean sweep?::It is first only on warping error. Methods with better Rand error use data-set-specific postprocessing on the earlier network's probability map (one team submitted 78 solutions), and DIVE-SCI beats it on Rand and pixel error. U-Net used no postprocessing, but averaged 7 rotated copies of the input.

#flashcards/research/concept #flashcards/topic/research-detection-segmentation How did U-Net do on the cell tracking challenge (paper's Table 2)?::First on both: IOU 0.9203 against the next 0.83 on PhC-U373, and 0.7756 against 0.46 on DIC-HeLa (about 32 points ahead, my arithmetic). #flashcards/research/concept #flashcards/topic/research-detection-segmentation What is intersection over union, with an example?::Overlap area divided by the area covered by prediction and truth together; 1 is perfect. Example: prediction 6 pixels, truth 8, 5 in common: $5/(6+8-5)=0.556$ (my arithmetic).

#flashcards/research/concept #flashcards/topic/research-detection-segmentation Why must the input tile size make every 2 by 2 pooling see an even size?::An odd width loses a row at the pooling and the later maps no longer line up for the copy. In the example 572, 568, 284, 280, 140, 136, 68, 64 are all even before pooling; a 573 tile would reach 569 (odd) (my arithmetic).
