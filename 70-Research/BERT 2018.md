# BERT 2018

> **In one line for a 12-year-old:** Hide some words in a sentence and make the network guess them from both sides. After that it understands language well enough to be tuned for many jobs.

Paper: "BERT: Pre-training of Deep Bidirectional Transformers for Language Understanding", arXiv 1810.04805, read as version 2 of 24 May 2019 (first page). Marks: "(paper, section)" was read in the paper; "(general knowledge)" is my own background; "(mine)" is my arithmetic.

## The problem
Use unlabelled text to build one model that many language tasks can start from. The authors' complaint about earlier pre-trained models: they read text in **one direction** only (left to right), which "restricts the power of the pre-trained representations", and is especially harmful for tasks like question answering where context from both sides matters (paper, introduction).

## What people did before
- **Feature-based:** ELMo ([[ELMo 2018]]) takes features from a left-to-right and a right-to-left language model trained separately and joins them; each task still needs its own architecture on top (paper, 1 and 2.1).
- **Fine-tuning:** OpenAI GPT trains a left-to-right [[Transformer]] and then fine-tunes all of it with few new parameters; each token can only look at tokens before it (paper, 1).
- Word vectors such as [[Word2Vec 2013]] came before both (paper, 2.1).

## The idea
Read the whole sentence at once, in both directions, in every layer, and train it with a cloze test: hide about 15% of the words and ask the model to fill them in. A second small task (is sentence B the real next sentence?) teaches it how two sentences relate. Then, for any task, add **one** small output layer and fine-tune everything (paper, 1 and 3). The analogy is a fill-in-the-blank exercise: you can use the words on both sides of the blank.

## The architecture (figures)
BERT is the **encoder half** of the Transformer ([[Attention Is All You Need 2017]]), stacked: "a multi-layer bidirectional Transformer encoder" (paper, 3). It has no decoder, so it reads text but does not write it. The same network is used in pre-training and in fine-tuning; only the output layer changes (paper, Figure 1 and 3).

### Comparison with its two rivals
| | BERT | OpenAI GPT | ELMo |
|---|---|---|---|
| What reads the text | a bidirectional Transformer | a left-to-right Transformer | two separate LSTMs, one left-to-right and one right-to-left |
| Context used | left and right, jointly, in all layers | left only | left and right, but only joined at the end |
| How it is used afterwards | fine-tune all parameters | fine-tune all parameters | take features, add a task-specific model |

### Part by part
- **Tokens: WordPiece with a 30,000-token vocabulary.**
  - *What it does:* text is split into word pieces (for example "playing" into "play" and "##ing") from a vocabulary of 30,000 (paper, 3).
  - *Why it matters:* a fixed vocabulary of pieces covers rare words without an unknown-word problem (general knowledge).
- **Special tokens: [CLS] and [SEP].**
  - *What it does:* the first token of every sequence is [CLS]; its final hidden vector $C$ is the summary of the whole sequence for classification. [SEP] separates two sentences (paper, 3).
  - *Why it matters:* one input format holds a single sentence or a pair, so one network fits many tasks. $C$ is not a meaningful sentence vector until fine-tuning, because it was only trained on next-sentence prediction (paper, footnote 6).
- **Input embedding: token plus segment plus position.**
  - *What it does:* each token's vector is the sum of three learned embeddings: the token itself, a segment embedding saying whether it is in sentence A or B, and a position embedding (paper, 3 and Figure 2).
  - *Why it matters:* attention alone ignores order and does not know which sentence a word belongs to; these two extra embeddings supply that. Unlike the original Transformer's fixed sine and cosine ([[Positional Encoding]]), BERT's positions are learned (paper; the comparison is general knowledge).

![[bert-input-embeddings.png]]
*BERT's input: the vector of each token is the sum of its token embedding, its position embedding and its segment embedding (A or B), with [CLS] at the front and [SEP] between and after the sentences. Image: Daniel Voigt Godoy, [Wikimedia Commons](https://commons.wikimedia.org/wiki/File:BERT_input_embeddings.png), CC BY 4.0. A redrawing of the idea of the paper's Figure 2, with a different example sentence ("alice follows the white rabbit"); the paper's own figure uses "my dog is cute" and "he likes playing", and the drawings otherwise show the same three rows.*

- **The encoder stack: $L$ layers, hidden size $H$, $A$ attention heads.**
  - *What it does:* each layer is a Transformer encoder block ([[Self-Attention]] then a feed-forward network, as in the Transformer). The paper reports two sizes: BERT-BASE ($L=12$, $H=768$, $A=12$, 110M parameters) and BERT-LARGE ($L=24$, $H=1024$, $A=16$, 340M). The feed-forward size is always $4H$ (3072 and 4096) (paper, 3 and its footnote 3). The activation is GELU, not ReLU, "following OpenAI GPT" (paper, A.2).
  - *Why it matters:* BASE was chosen to be the same size as OpenAI GPT so the comparison isolates the effect of reading in both directions. LARGE exists to see what size does. (The paper does not explain why these particular numbers, 12 and 768, and 24 and 1024; the evidence for size is Table 6 below.)
- **The output layer added for each task.**
  - *What it does:* during fine-tuning only one small layer is new: for classification a weight matrix on the [CLS] vector; for span answers a start vector and an end vector; for tagging a classifier on each token's vector (paper, 3.2 and 4).
  - *Why it matters:* the model does almost all the work, so very little must be learned from the small labelled data set. The paper says that larger models help even on tiny tasks "provided that the model has been sufficiently pre-trained" (paper, 5.2).

## The core mechanism, step by step

### Pre-training task 1: the masked language model
**The idea.** A normal language model guesses the next word from the words before it. A bidirectional model cannot do that, because "bidirectional conditioning would allow each word to indirectly 'see itself'" in a multi-layer network and predict the target trivially (paper, 3.1). The fix is to hide the target words from the input.

![[bert-masked-lm-task.png]]
*The masked language model: a few input tokens are replaced by [MASK] (here the word piece "##ica" becomes [MASK]); BERT, a Transformer encoder, reads the whole sequence, and the vector at the masked position goes through an output layer that gives scores (logits) over the vocabulary. Image: Daniel Voigt Godoy, [Wikimedia Commons](https://commons.wikimedia.org/wiki/File:BERT_masked_language_modelling_task.png), CC BY 4.0. A redrawing of the idea of the left half of the paper's Figure 1; it also shows the token ids and has no sentence pair, which the paper's figure has.*

1. **Pick positions at random: 15% of the tokens.**
   - *What it does:* the training data generator chooses 15% of the WordPiece positions in every sequence (paper, 3.1). My arithmetic: in a 512-token sequence that is 76.8 positions on average.
   - *Why it matters:* enough targets to learn from, but most of the sentence stays visible as context. (The paper does not test other percentages in the pages I read.)
2. **Change those tokens: 80% [MASK], 10% a random token, 10% unchanged.**
   - *What it does:* of the chosen positions, about 61 become [MASK], about 8 become a random word and about 8 stay as they were (my arithmetic for 512 tokens) (paper, 3.1).
   - *Why it matters:* the [MASK] symbol never appears when the model is later fine-tuned, so the pre-training and fine-tuning inputs would not match. Leaving some tokens unchanged or random forces the model to build a good representation of *every* word, because it cannot tell which ones are targets. The evidence is the paper's Table 8 below.
3. **Run the whole sequence through the encoder.**
   - *What it does:* every token attends to every other token, left and right, in every layer.
   - *Why it matters:* this is the "deep bidirectional" part; the representation of a word uses both sides.
4. **Predict the original words at the chosen positions only.**
   - *What it does:* the final vector of each chosen position goes to a softmax over the vocabulary and the loss is the cross entropy with the original token. Unlike a denoising autoencoder, it predicts only the masked words, not the whole input (paper, 3.1).
   - *Why it matters:* this is what makes the training signal. The cost: only 15% of tokens give a signal per sequence, so it "converges marginally slower" than a left-to-right model, but the paper says the gains far outweigh that (paper, A.1 and C.1).

**Worked example (mine; two masked words).** Suppose the model gives the true word a probability of 0.5 at one masked position and 0.25 at the other. The two losses are $-\ln0.5=0.693$ and $-\ln0.25=1.386$, and their mean is $1.040$. A model that grew more certain would lower this number.

**What each column is, and why it matters**
- **MASK, SAME, RND:** how the chosen 15% of tokens are treated in pre-training (the first row is BERT's recipe). It matters because it is the only thing that changes between rows.
- **MNLI (fine-tune):** accuracy on sentence-pair inference after fine-tuning all weights.

- **Fine-tuning is "surprisingly robust":** MNLI stays between 83.6 and 84.4 and NER fine-tuning between 94.8 and 95.4 across all six recipes, so the exact split matters little there.

### Pre-training task 2: next sentence prediction
**The idea.** Many tasks (question answering, inference) depend on how two sentences relate, which language modelling does not capture directly. So the model also learns a yes-or-no question about pairs (paper, 3.1).

![[bert-next-sentence-task.png]]
*Next sentence prediction: sentence A and sentence B are packed into one sequence with [CLS] first and [SEP] between and after; the vector at [CLS] goes through an output layer that gives the two scores (logits) for "B follows A" and "B is random". Image: Daniel Voigt Godoy, [Wikimedia Commons](https://commons.wikimedia.org/wiki/File:BERT_next_sequence_prediction_task.png), CC BY 4.0. A redrawing of the idea of the right half of the paper's Figure 1 with a different example.*

1. **Build a pair.**
   - *What it does:* for each training example, sentence B is the real next sentence 50% of the time (label IsNext) and a random sentence from the corpus 50% of the time (NotNext). The "sentences" are really spans of text, up to 512 tokens together (paper, 3.1 and A.2).
   - *Why it matters:* the labels cost nothing: any plain text file makes them.
2. **Pack and encode.**
   - *What it does:* [CLS] A [SEP] B [SEP], with segment embeddings A and B, goes through the encoder.
   - *Why it matters:* the same self-attention lets every token of A attend to every token of B, so the pair is read as one text.
3. **Classify from [CLS].**
   - *What it does:* the vector $C$ goes to a classifier for IsNext or NotNext. The final model reaches 97% to 98% accuracy on this task (paper, footnote 5).
   - *Why it matters:* it trains $C$ to summarise the pair. Removing the task hurts several tasks (paper's Table 5 below).

### The pre-training recipe
- **Data:** BooksCorpus (800M words) plus English Wikipedia (2,500M words), text passages only, taken as long documents and not shuffled sentences, "in order to extract long contiguous sequences" (paper, 3.1). Together 3.3 billion words (paper, A.2).
- **Batch and steps:** 256 sequences of up to 512 tokens, which is 131,072 tokens per batch, for 1,000,000 steps, about 40 passes over the data (the paper says "approximately 40 epochs"; my arithmetic gives 39.7 counting tokens as words).
- **Optimiser:** Adam with learning rate $10^{-4}$, warm-up over 10,000 steps then linear decay, weight decay 0.01, dropout 0.1 (paper, A.2).
- **Loss:** the sum of the mean masked-LM likelihood and the mean next-sentence-prediction likelihood (paper, A.2).
- **Length trick:** 90% of the steps use sequences of 128 tokens and the last 10% use 512 "to learn the positional embeddings", because attention costs grow with the square of the length (paper, A.2). My arithmetic: attention work at 128 tokens is $(128/512)^2=1/16$ of that at 512.
- **Hardware and time:** BERT-BASE on 4 Cloud TPUs (16 chips), BERT-LARGE on 16 Cloud TPUs (64 chips), each pre-training 4 days (paper, A.2).

### Fine-tuning: one small layer per task
1. **Initialise from the pre-trained weights.** Each task starts from the same pre-trained model but gets its own fine-tuned copy (paper, 3).
2. **Feed the task's input in the same packed format:** a single sentence, a sentence pair, a question and a passage, or a sentence plus a possible continuation (paper, 3.2).
3. **Add one small output layer and train everything end to end,** every weight included (paper, 3.2).

| Task | Input | New part | Source |
|---|---|---|---|
| GLUE (classification) | one sentence or a pair | weight matrix $W$ ($K\times H$) on the [CLS] vector, then a softmax over $K$ labels | paper, 4.1 |
| SQuAD v1.1 (find the answer in a passage) | question as sentence A, passage as sentence B | a start vector $S$ and an end vector $E$ | paper, 4.2 |
| SQuAD v2.0 (the answer may not exist) | the same | the same; "no answer" is a span that starts and ends at [CLS] | paper, 4.3 |
| SWAG (pick the sensible continuation of four) | four sequences, each the sentence plus one continuation | one vector whose dot product with [CLS] scores each choice, then a softmax over the four | paper, 4.4 |
| NER (tag names in text) | one text | a classifier on the first sub-token of each word, no CRF layer | paper, 5.3 |

*A table written by me from the paper's text.*

Fine-tuning is cheap next to pre-training: "all of the results in the paper can be replicated in at most 1 hour on a single Cloud TPU, or a few hours on a GPU", and a SQuAD model in about 30 minutes (paper, 3.2 and its footnote 7). GLUE used batch size 32 and 3 epochs, with the learning rate chosen from $5\text{e-}5$, $4\text{e-}5$, $3\text{e-}5$ and $2\text{e-}5$ on the Dev set; BERT-LARGE was sometimes unstable on small sets, so several random restarts were run and the best on Dev was kept (paper, 4.1).

## The equations
These are not numbered equations in the paper; they are its written definitions, set here as displays so each term can be explained (paper sections cited).

**1. The input representation** (section 3, Figure 2)

$$
x_i=E^{\text{token}}_i+E^{\text{segment}}_i+E^{\text{position}}_i
$$

**Where:**
- $x_i$: the vector fed into the first layer for the $i$-th token.
- $E^{\text{token}}_i$: the learned vector for that word piece. $E^{\text{segment}}_i$: the learned vector for sentence A or sentence B. $E^{\text{position}}_i$: the learned vector for position $i$.

**Matters:** attention treats the tokens as an unordered set, so without the position vector the model could not tell "dog bites man" from "man bites dog" (general knowledge), and without the segment vector it could not tell which sentence a token belongs to. Adding keeps the size at $H$ numbers.

**Example (tiny numbers):** a three-number embedding. $E^{\text{token}}=(0.2,0.1,0.0)$, $E^{\text{position}}=(0.0,0.1,0.1)$, $E^{\text{segment}}=(0.1,0.0,0.1)$.
- Sum: $(0.2+0.0+0.1,\ 0.1+0.1+0.0,\ 0.0+0.1+0.1)=(0.3,\,0.2,\,0.2)$.
- Meaning: one vector carries what the word is, where it is, and which sentence it is in.

**2. The pre-training loss** (appendix A.2)

$$
\mathcal{L}=\mathcal{L}_{\text{MLM}}+\mathcal{L}_{\text{NSP}}
$$

**Where:**
- $\mathcal{L}_{\text{MLM}}$: the mean masked-language-model loss (the negative log-likelihood of the correct word, averaged over the masked positions).
- $\mathcal{L}_{\text{NSP}}$: the mean next-sentence-prediction loss (negative log-likelihood of the correct IsNext or NotNext label).

**Matters:** one model learns both tasks at the same time from one loss; each task pushes the same weights. The paper states the loss as a sum "of the mean masked LM likelihood and the mean next sentence prediction likelihood" without weights.

**Example (tiny numbers):** two masked words predicted with probabilities 0.5 and 0.25, and the next-sentence label predicted with probability 0.8.
- $\mathcal{L}_{\text{MLM}}=(0.693+1.386)/2=1.040$; $\mathcal{L}_{\text{NSP}}=-\ln0.8=0.223$.
- $\mathcal{L}=1.040+0.223=1.263$.
- Meaning: the single number to be pushed down is the sum of how surprised the model was by the masked words and by the sentence relation.

**3. The classification loss for fine-tuning** (section 4.1)

$$
\text{loss}=-\log\operatorname{softmax}\!\left(CW^{T}\right)_{y}
$$

**Where:**
- $C\in\mathbb{R}^{H}$: the final vector of the [CLS] token. $W\in\mathbb{R}^{K\times H}$: the new classification weights, $K$ labels.
- $y$: the true label; the subscript picks its probability. (The paper writes "$\log(\operatorname{softmax}(CW^{T}))$" as the standard classification loss; I add the minus sign and the label index to make it a loss to be minimised.)

**Matters:** $W$ is the only new part; the loss pushes $C$ and $W$ so the true label gets a high probability.

**Example (tiny numbers):** $H=2$, $K=2$, $C=(1,2)$, $W=\begin{pmatrix}1&0\\0&1\end{pmatrix}$, true label 2.
- $CW^{T}=(1,2)$; softmax: $(0.269,\,0.731)$.
- Loss $=-\ln0.731=0.313$.
- Meaning: the model puts 73% on the right label, so the loss is small.

**4. The span answer for question answering** (sections 4.2 and 4.3)

$$
P_i=\frac{e^{S\cdot T_i}}{\sum_j e^{S\cdot T_j}},\qquad \text{score}(i,j)=S\cdot T_i+E\cdot T_j\ \ (j\ge i)
$$

**Where:**
- $T_i\in\mathbb{R}^{H}$: the final vector of the $i$-th token of the passage. $S$ and $E$: the new start and end vectors learned in fine-tuning.
- $P_i$: the probability that token $i$ starts the answer (an analogous formula gives the end). The score of a candidate span from $i$ to $j$ adds the start score of $i$ and the end score of $j$; the best span with $j\ge i$ is the answer.
- For SQuAD 2.0 the "no answer" score is $s_{\text{null}}=S\cdot C+E\cdot C$, and a real answer is given only when $\hat s_{i,j}>s_{\text{null}}+\tau$, with $\tau$ chosen on the Dev set to maximise F1.

**Matters:** answering a question needs only two new vectors; the dot products read the start and end off the contextual token vectors.

**Example (tiny numbers):** three passage tokens $T_1=(1,0)$, $T_2=(0,1)$, $T_3=(2,1)$, $S=(1,0)$, $E=(0,1)$.
- $S\cdot T=(1,0,2)$, so the start probabilities are $(0.245,\,0.090,\,0.665)$.
- Span scores $S\cdot T_i+E\cdot T_j$: $(1,1)=1$, $(1,2)=2$, $(1,3)=2$, $(2,2)=1$, $(2,3)=1$, $(3,3)=3$. The best span is token 3 alone.
- With $C=(0.5,0.5)$, $s_{\text{null}}=1$; with $\tau=1$ the span's 3 beats $1+1=2$, so an answer is given.
- Meaning: the model picks the highest-scoring span and answers only if it clearly beats "no answer".

## What they found
BERT reached new best results on eleven tasks, including GLUE 80.5% (7.7 points absolute gain), MultiNLI 86.7% (+4.6), SQuAD v1.1 Test F1 93.2 (+1.5) and SQuAD v2.0 Test F1 83.1 (+5.1) (abstract; the paper's text confirms each in sections 4.1 to 4.3). The ablations show bidirectionality is the key ingredient (Table 5), size helps even small tasks (Table 6, above), and the same pre-trained model also works as a frozen feature extractor (Table 7).

## Questions I had, answered

**Is BERT a text generator like GPT?** No. It is the Transformer's encoder only, trained to fill in blanks, so it reads text but does not write it (paper, 3, and the footnote saying the left-context-only version is usually called a "Transformer decoder" because it can generate text). The paper says BERT and OpenAI GPT are nearly identical in architecture apart from the attention masking.

**Why does bidirectional reading need the masking?** In a deep bidirectional model every word can, through the layers, indirectly "see itself", so predicting a word from its own surroundings would be trivial (paper, 3.1). Hiding the target word removes that leak, which is why the cloze task is the training signal.

**Why is [MASK] a problem, and how is it handled?** The [MASK] symbol appears in pre-training but never when you later fine-tune, creating a mismatch. BERT lowers it by replacing only 80% of the chosen words with [MASK], 10% with a random word and 10% with the original (paper, 3.1). Table 8 shows fine-tuning is robust to the exact split.

**What is the [CLS] vector?** The final vector of the first token, used as the summary of the whole sequence for classification. It is not a good sentence vector before fine-tuning, because it was trained only for next-sentence prediction (paper, 3 and footnote 6).

**Is fine-tuning expensive?** No compared with pre-training: at most an hour on one Cloud TPU for the paper's results, against 4 days on 16 or 64 TPU chips for pre-training (paper, 3.2 and A.2).

**Does bigger always help?** In Table 6, yes, even for a task with only 3.5 thousand labelled examples. The authors suggest that when a model is fine-tuned directly with very few new parameters, it can use bigger, richer pre-trained representations even on little data; earlier feature-based work had mixed results (paper, 5.2).

## Why it mattered
Made "pre-train, then fine-tune" the default for language understanding.

## Limits and open questions
- An encoder that reads text, not a text generator, so it is not used for chat ([[LLM]]).
- The masked task trains on only 15% of tokens per sequence, so pre-training converges a bit slower than a left-to-right model (paper, C.1).
- Pre-training is expensive (4 days on 16 to 64 TPU chips, plus the data) (paper, A.2).
- The [MASK] mismatch between pre-training and fine-tuning is reduced, not removed (paper, 3.1).
- The paper reports single-task fine-tuning only; multi-task fine-tuning might improve results further (paper, B footnote 14).
- Several ablations use one run per row with no spread (Tables 5 and 6 above).

#flashcards/research/concept #flashcards/topic/research-nlp Write BERT's input representation and explain each symbol.
?
$$x_i=E^{\text{token}}_i+E^{\text{segment}}_i+E^{\text{position}}_i$$
- $x_i$: the vector fed into layer 1 for token $i$; the three terms are the learned token, segment (sentence A or B) and position embeddings.

#flashcards/research/concept #flashcards/topic/research-nlp Write BERT's pre-training loss and explain each symbol.
?
$$\mathcal{L}=\mathcal{L}_{\text{MLM}}+\mathcal{L}_{\text{NSP}}$$
- $\mathcal{L}_{\text{MLM}}$: mean negative log-likelihood of the correct word over the masked positions. $\mathcal{L}_{\text{NSP}}$: negative log-likelihood of the correct IsNext or NotNext label.
- One model learns both tasks at once from the sum of the two (no weights, as the paper states it).

#flashcards/research/concept #flashcards/topic/research-nlp Pre-training loss example: masked words predicted with probabilities 0.5 and 0.25, next-sentence label with 0.8. What is the loss?
?
$\mathcal{L}_{\text{MLM}}=(0.693+1.386)/2=1.040$; $\mathcal{L}_{\text{NSP}}=-\ln0.8=0.223$; total $1.263$ (my arithmetic).

#flashcards/research/concept #flashcards/topic/research-nlp Write BERT's classification loss for fine-tuning and explain each symbol.
?
$$\text{loss}=-\log\operatorname{softmax}\!\left(CW^{T}\right)_{y}$$
- $C$: the final [CLS] vector. $W$ ($K\times H$): the new classification weights for $K$ labels. $y$: the true label.
- $W$ is the only new part. (The paper writes $\log(\operatorname{softmax}(CW^T))$; the sign and label index are added to make it a loss.)

#flashcards/research/concept #flashcards/topic/research-nlp Classification loss example: $C=(1,2)$, $W$ the identity matrix, true label 2. What is the loss?
?
$CW^T=(1,2)$; softmax $(0.269,0.731)$; loss $-\ln0.731=0.313$ (my arithmetic).

#flashcards/research/concept #flashcards/topic/research-nlp Write BERT's span-answer formulas and explain each symbol.
?
$$P_i=\frac{e^{S\cdot T_i}}{\sum_j e^{S\cdot T_j}},\qquad \text{score}(i,j)=S\cdot T_i+E\cdot T_j\ \ (j\ge i)$$
- $T_i$: the final vector of passage token $i$; $S$ and $E$: the new start and end vectors; $P_i$: probability that token $i$ starts the answer.
- The best-scoring span is the answer. For SQuAD 2.0, the null score is $S\cdot C+E\cdot C$ and an answer is given only if the span beats it by more than a threshold $\tau$ set on the Dev set.
